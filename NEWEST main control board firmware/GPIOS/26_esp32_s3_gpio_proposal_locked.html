REII Lock-In Rationale (from Group Report v3)

1. SPI2 Shared Bus — Already Locked (MEASURED + SHARED)

  • GPIO 11 — SPI2 MOSI → J1.2 → nRF24L01+ MOSI — Measured in boot log, shared SPI2
  • GPIO 12 — SPI2 SCK → J1.3 → nRF24L01+ SCK — Measured in boot log, shared SPI2
  • GPIO 13 — SPI2 MISO → J1.4 → nRF24L01+ MISO — Measured in boot log, shared SPI2

2. nRF CSN — Locked Now (was PROPOSED)

GPIO 17 → J1.1 → nRF24L01+ CSN

Evidence: Group Report v3 Table 43 confirms "pull all SPI2 chip-select pins HIGH (GPIO17 nRF24...)"

⚠ GPIO17 floats in starter firmware — drive HIGH at boot before first SPI transaction.

3. nRF CE — Locked Now (J7.10)

GPIO 10 → J7.10 → nRF24L01+ CE

Evidence: Group Report v3 Table 43 references "Header J1 & J7.10" for crane SPI2 bus. docs/27 §3 Option B: CE=GPIO10, IRQ=none (poll STATUS). Resolves CONTEST with MC2.

4. IRQ — Disconnected / Freed (was CONTESTED)

GPIO 18 → J7.9 → was nRF IRQ / MC2

Evidence: Group Report v3 Table 43: "Poll SPI STATUS ... so J7.9 (GPIO18) stays free for MCTR 1". IRQ disconnected; pin released from REII.

5. +3.3VP Power Gate — Already Locked (VERIFIED + CRITICAL)

GPIO 47 → +3.3VP rail enable → J1.8 → nRF VCC

Evidence: Measured + verified. GPIO47 must be HIGH before any nRF SPI init. Back-power path on I2C pull-ups — keep HIGH when peripherals active.

6. Fallback — PROPOSED (not locked)

GPIO 16 → nRF CE fallback candidate

Kept as PROPOSED fallback only. Activate only if GPIO 10 proves unusable.
