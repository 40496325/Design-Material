⚠ Core Pin Contention Summary (§7)

The core board exposes 7 free GPIOs on J7 (1, 4, 10, 18, 21, 41, 42) + 1 spare CS on J1.1 (17), plus 3 active SPWM pins (38, 39, 40).

  • EE1 (6 gate/PWM) claims J7.3–J7.8 (1, 42, 41, 40, 39, 38), leaving no free pin for its +1 reserve or EE2's magnet PWM.
  • MC2 (4 trolley lines) claims J7.9–J7.12 (18, 10, 4, 21), which directly contests REII nRF CE/IRQ candidates (GPIO 10 / 18).

Why Slide 7's Math Cannot Be Reproduced Here:

Slide 7 states "26 committed of 34 usable GPIO… 8 pins margin — 4 free, 4 strapping-reserved". On this physical board, the listed items sum to 22, and J7 exposes only 10 signal GPIOs (plus UART0 on 43/44). Therefore, slow signals must migrate to the MCP23017 (J3/J4) and/or the student IO board, or the package split must change at group ICD decision D-06.

§8. Conflicts, Cautions & Open Items (Reported, Not Silently Resolved)

Critical hardware traps, net naming mismatches, and specification discrepancies from Doc 26

1. Net `IO6` Sits on GPIO1 (Not GPIO6!) J7.3 Anomaly

Schematic net IO6 is routed to GPIO1 (WROOM pin 39 → J7.3), whereas GPIO6 carries PX_INTB (MCP23017 interrupt B). Never assume J7.3 = GPIO6; confirm with board owner.

2. Module Variant Conflict (8 MB vs 16 MB) Contradiction #5

SysRS DR5 specifies ESP32-S3-WROOM-1 (N8R2) (8 MB flash / 2 MB PSRAM); schematic U1 = WROOM-1U (external antenna); overview says 16 MB flash / 8 MB PSRAM; measured boot = 16 MB flash. Query lecturer/board owner.

3. J1.7 (+5V) Next to J1.8 (+3.3VP) Fatal Hardware Risk

On the 10-pin J1 header, Pin 7 (+5V) is immediately adjacent to Pin 8 (+3.3VP). Plugging +5V into nRF24L01+ VCC destroys the radio module (docs/27 §1). Key harness to Pin 8 only.

4. +3.3VP is Firmware-Gated (GPIO47) & Back-Power Path Power Rule

Clearing GPIO47 kills +3.3VP (including any radio on J1.8). Meanwhile, I2C pull-ups (R8/R9) sit on always-on +3.3V, creating a back-power path when +3.3VP is off. Rule: keep GPIO47 HIGH whenever peripherals/radio are used.

5. GPIO17 (`SPI_xCS` on J1.1) Floats Today SPI2 Bus Init

Starter firmware never configures GPIO17. Any SPI device attached to J1 sees an undefined CSN until firmware explicitly drives GPIO17 output-high at boot before SPI2 init.

6. Console UART0 Ambiguity (GPIO 43 / 44) J7.1 / J7.2

Boot log prints "GPIO 44 and 43 are used as console UART I/O pins" yet all monitor output arrived via native USB COM12 (GPIO19/20). Measure whether J7.1/J7.2 carry live UART traffic before touching them.

7. Lecture Handling Gates (Course Authority) Mandatory

All pins strictly 0–3 V; no WiFi without external antenna (starter removed WiFi to prevent PA damage); respect external-5V abuse limit; 5V (D7) + 3VS (D1) LEDs must light or stop immediately.

8. Unsigned Draft ICD Status (`ICD_REII.pdf`) D-09 / D-06

ICD_REII.pdf is an unsigned draft: "ESP IO header" pins are TBD and it still names an STM32F411 ground station (superseded by NodeMCU-32S per D-08/D-09). Identifying J1 as that header is PROPOSED here.
