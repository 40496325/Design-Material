## Latency budget check (for the dashboard 50 ms fault-display requirement)

```
T_frame(250 kbps, 32 B payload, 5 B addr, 2 B CRC, 9 bit PCF) ≈ (8 + 40 + 256 + 16 + 9) / 250e3 ≈ 1.3 ms
T_ack                                                        ≈ 0.2 ms (empty ACK) … 1.3 ms (32 B ACK payload)
worst case one packet = ARC × (T_frame + ARD + T_ack) = ___ ms  → must stay < 50 ms − dongle/USB/dashboard latency
```

## What this feeds into

* STM32F411 dongle nRF24 driver: the exact register values above (`CONFIG`, `EN_AA`, `SETUP_RETR`, `RF_CH`, `RF_SETUP`, `SETUP_AW`, `RX_PW_P*`) become the init table.
* ESP32-S3 controller stubbed SPI driver: same init table, RX role.
* Protocol design (SoW item 2): the measured PER and retry statistics decide whether ACK/retry at the radio layer is enough or an application-level ARQ / heartbeat is needed.
